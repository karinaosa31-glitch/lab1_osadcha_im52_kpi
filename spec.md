# Специфікація моделі даних (spec.md)

## 1. Сутності та атрибути

### book (Книга)
Описує бібліографічні дані видання в каталозі бібліотеки.
- `book_id` (PK) — унікальний ідентифікатор книги.
- `title` — назва книги.
- `genre` — жанр або категорія видання.
- `ISBN` (UK) — міжнародний стандартний номер книги (унікальний).
- `year_of_publication` — рік публікації видання (ціле число більше 0 і не більше поточного року).
- `pages_count` — кількість сторінок (ціле число більше 0).
- `language` — мова видання (за замовчуванням Ukrainian).

### author (Автор)
Зберігає інформацію про авторів книг.
- `author_id` (PK) — унікальний ідентифікатор автора.
- `author_name` — повне ім'я або псевдонім автора.
- `country` — країна походження автора.

### copy (Фізичний примірник)
Представляє окрему фізичну копію книги у фонді бібліотеки.
- `copy_id` (PK) — унікальний ідентифікатор примірника.
- `book_id` (FK -> `book.book_id`) — ID книги в каталозі.
- `inventory_number` (UK) — унікальний бібліотечний інвентарний номер.
- `shelf_location` — місце зберігання примірника (стелаж, полиця).
- `book_condition` — опис фізичного стану книги.
- `status` — статус доступності примірника (`available`, `borrowed`, `damaged`, `lost`).

### reader (Читач)
Позначає зареєстрованого користувача бібліотеки, який може брати книги.
- `reader_id` (PK) — унікальний ідентифікатор читача.
- `reader_name` — прізвище та ім'я читача.
- `phone_number` — контактний номер телефону.
- `email` (UK) — електронна пошта читача (унікальна).
- `registration_date` — дата реєстрації в бібліотеці.
- `status` — статус облікового запису читача (`active`, `blocked`, `inactive`).

### librarian (Бібліотекар)
Позначає працівника бібліотеки, який обслуговує читачів та оформлює видачу книг.
- `librarian_id` (PK) — унікальний ідентифікатор бібліотекаря.
- `librarian_name` — прізвище та ім'я бібліотекаря.
- `email` (UK) — робоча електронна пошта (унікальна).

### borrowing (Видача книги)
Описує факт видачі конкретного фізичного примірника читачеві та його повернення.
- `borrowing_id` (PK) — унікальний ідентифікатор операції видачі.
- `copy_id` (FK -> `copy.copy_id`) — ID фізичного примірника книги.
- `reader_id` (FK -> `reader.reader_id`) — ID читача, який взяв книгу.
- `librarian_id` (FK -> `librarian.librarian_id`) — ID бібліотекаря, який оформив видачу.
- `borrow_date` — дата видачі книги.
- `due_date` — планова дата повернення книги (не менша за `borrow_date`).
- `return_date` — фактична дата повернення (`NULL`, якщо книга ще не повернута).
- `fine_status` — статус штрафу за прострочення (`not overdue`, `overdue`, `paid`).
- `fine_amount` — сума нарахованого штрафу (невід'ємне число).

## 2. Зв'язки між сутностями

- `book` ↔ `author` (M:N): Одна книга може бути написана кількома авторами, а один автор — створити багато книг.
- `book` ↔ `copy` (1:N): Одне видання в каталозі може мати багато фізичних примірників.
- `copy` ↔ `borrowing` (1:N): Один фізичний примірник може видаватися в межах багатьох операцій видачі в різний час.
- `reader` ↔ `borrowing` (1:N): Один читач може оформити багато видач книг.
- `librarian` ↔ `borrowing` (1:N): Один бібліотекар може оформити багато видач книг.

## 3. Критерії прийняття (Acceptance Criteria)

- Модель даних повинна бути нормалізована (3NF).
- Усі зв'язки між сутностями предметної області мають бути явними, без додавання технічних сполучних таблиць без власних атрибутів.
- Кожна сутність повинна мати Primary Key.
- Зовнішні ключі (Foreign Keys) мають чітко посилатися на відповідні первинні ключі батьківських сутностей.
- Домени значень (статуси, дати, суми штрафів, унікальні коди ISBN та інвентарні номери) повинні бути захищені відповідними обмеженнями цілісності.
